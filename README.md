Portfolio Reflection


How I Used AI

I am a beginner in Python, and my previous field of study was not programming. Sometimes programming concepts are difficult for me to understand, and English technical terms make learning harder. While completing this semester’s weekly projects, I used AI to explain Python code and assignment instructions in simple language. I also asked it to help me understand error messages, check code, and review test results.

In the first few weeks, I gradually learned to use variables, conditional statements, loops, functions, and lists to complete programming tasks. Later, I started learning about dictionaries, modules, CSV files, and Pandas, and tried using code to process and analyze data. For these projects, I asked AI to explain unfamiliar code or help me find problems.

As I used AI, I learned that I should not use an answer just because AI provided it. I need to check that the code meets the assignment requirements and make sure I understand what it does.

Challenges I Faced

My challenges included understanding new programming concepts, deciding whether AI-generated code was correct, and finding out why code did not run as expected.

A specific example was writing and testing code to check whether a year is a leap year. I found that checking only whether a year is divisible by 4 is not enough. For example, 1900 is divisible by both 4 and 100, but not by 400, so it is not a leap year. This helped me understand that tests should cover not only normal cases but also boundary and special cases.

How I Solved or Documented Them

When I did not understand a problem, I broke it into smaller parts and first checked the assignment requirements. If the code did not work as expected, I looked at the error message and checked the relevant code and variables. I also used specific inputs and expected results to test the code. If a line of code was still unclear, I asked AI to explain it in simple language. When AI gave me code that seemed too complicated, I asked it to explain or rewrite it more simply, and then checked it myself.

For the leap-year code, I tested a typical leap year, a year that is not divisible by 4, a year divisible by 100 but not by 400, and a year divisible by 400. I also checked the rules and the code’s decision logic to identify the special case of 1900. Testing different years helped me see whether the code followed the requirements.

These steps helped me understand more than just the answer; they helped me gradually understand the problem-solving process. This semester, I learned that AI can support my learning and programming, but I still need to judge whether the code is correct, meets the requirements, and is easy to understand. In the future, I will first clarify the problem and expected result, then use AI to help with the code, and verify the result through testing, debugging, and checking.
